# FazeMES

<img src="frontend/public/fazemes-logo.svg" alt="FazeMES" width="64" height="64">

FazeMES 是基于 Spring Boot、Vue 3 和 TypeScript 的生产执行管理系统，供 Windows 本地开发和工厂业务适配使用。

## 功能范围

- **基础资料**：物料、产品、BOM、工艺路线、车间与工作站。
- **生产管理**：工单、排产、领料、报工、工序流转与完工。
- **生产决策中心**：交期风险预警、插单与加班方案仿真、质量关联、异常处置验证闭环、实时业务问答及流程瓶颈分析，详见[使用说明](deploy/PRODUCTION-INSIGHT.md)。
- **齐套缺料**：按工单 BOM、净领料及可用库存分析缺口，支持工单预占、释放和到料跟进。
- **受控作业**：SOP 审批发布、任务版本快照、步骤确认、参数及照片留痕，未完成必做步骤时拦截报工。
- **单件追溯**：SN 登记与工序过站，将已完成报工的实际耗料分摊到单件，支持按物料批次反查。
- **报表与大屏**：拖拽式 A4 报表画布、组件与白名单数据绑定、版本发布、Excel 导出与打印，以及带城市地图和 Three.js 动效的生产看板。
- **AI 与知识库**：文档上传解析、分块检索与来源引用、独立会话；支持配置 OpenAI 兼容 API Key 或本地 Ollama。
- **Jev 异常分流试点**：异常分类、实际部门建议、人工确认与采纳记录；使用独立的 TypeSafe 密钥，详见 [Jev 接入说明](deploy/JEV-TRIAGE.md)。
- **业务助手成本查询**：按产品／工单编码查询标准及实际成本，复用价格与成本模块和独立查询权限；协作更新与 Agent 适配见[合并说明](deploy/UPSTREAM-INTEGRATION.md)。
- **客户门户**：独立客户账号、发布产品目录、订购申请审核及本客户生产进度查询。
- **人脸登录**：密码确认后录入本人人脸，通过本地 SFace 一对一核验登录，可停用并清除特征。
- **仓库管理**：库存、入库、出库、调拨、盘点与装箱。
- **配套管理**：质量、设备、工装夹具、班组与排班。
- **系统管理**：账号、角色、菜单、租户及本地附件存储。

当前启用 MES、系统管理和基础设施模块，并提供虚构示例数据。
前端以统一工作台为首页，业务导航按生产、质量追溯、仓库、设备工装、基础工艺和报表看板分组，常用入口按账号已有授权显示。原“MES 首页”地址跳转到工作台，人脸登录设置移至头像菜单。

“系统设置”保留已授权的账号、角色、组织、字典、公告和审计入口；菜单维护、租户套餐、第三方集成配置及“基础设施”不出现在交付导航和菜单搜索中。后台附件、配置、日志和调度服务继续供业务模块使用，原有页面地址和操作权限保留。

## Faze-UP Broky 产品示例

`BROKY-FG-V2` 是一款可调速摆头落地扇的教学制造案例，包括动力机头、立柱底座两种自制半成品和 28 种采购物料。三级 BOM 共 30 行，整机本层 17 项；采购叶子排除包装后有 24 种制造物料。三条路线共 11 道工序，只有末道关键工序经检验后产生产品库存。父工单领用半成品，子工单领用各自原料，避免重复领料。

“价格与成本”可查看 BOM 树、采购叶子汇总、版本价格、工单冻结计划及实际成本、采购入库价和销售毛利。金额均为人民币、不含税。示例预算为材料 148 元、人工 18 元、制造费用 6 元，总标准成本 **172 元**，标准售价 **299 元**；机头、底座标准成本分别为 85.50 元、31.50 元。上述金额是教学预算，并非供应商报价或实测成本。

新增迁移由启动脚本按顺序执行：`20261018_broky_cost.sql`、`20261018_broky_integrity.sql`、`20261018_broky_product.sql`。产品迁移只补缺失配置，身份冲突会中止回滚，保留后续价格和业务操作。初始仅一张 100 台父工单草稿，不预置库存、完成交易、质检结果或审批。

```powershell
python -X utf8 deploy/verify-broky-product.py
python -X utf8 deploy/verify-broky-product.py --base http://127.0.0.1:48080/admin-api
python -X utf8 deploy/verify-broky-product.py --base http://127.0.0.1:48080/admin-api --publish-demo-configuration
```

第一条离线检查配置；第二条认证后只读检查；第三条在核对内容后通过正常 API 发布教学 SOP、启用模板和物料及路线。凭据从本地 `.runtime/secrets.local.json` 读取。配置发布不表示实物已检验或认证，实际检验依据及技术参数仍需工艺和质量负责人审核。

正常流程为采购到货、来料检验与入库，确认父工单，再按其本层 BOM 分别生成 100 套机头和底座子工单。子工单完成生产、检验、入半成品仓、完工及成本结算后，才能带已确认成本投入父工单。原料入库需填写供应商批号；自制品按工单及生产日分批。工单确认时冻结本层 BOM 与价格计划；配方必须与工艺定额一致，修改使用新产品/工艺版本。排产及报工总量受工单容量和前序合格数量约束。

前序出现损耗时，可从工单列表选择“损耗结案”。系统逐工序核对投入、合格及不良数量，要求全部报工已完成、线边库存已清理、子工单已收尾，再保存结案原因、操作者和各工序证据；原计划和报工不被改写。损耗子工单按实际合格产出占用父工单需求，允许为缺口补建子工单。

不合格销售退货、生产退料、外协收货及关联不合格 IQC 的采购入库必须进入“不良隔离仓”，待检物料不得入库。隔离仓禁止销售、领料、调拨及盘亏等出库，齐套与出库选择不计入这部分库存；新租户可在仓库管理中按权限幂等初始化隔离仓。`20261019_quality_quarantine.sql` 会为能由历史实际流水可靠定位的混入库存及后续成对调拨库存加持久待核对标记，保持原数量及流水不变；无法可靠定位的异常留作人工核查。库存页“历史质量核查”可查看来源证据，普通解冻不会解除质量管控，也不代表实物已完成核对。

领料行及拣货明细保存后固定原单据归属，已完成、已取消记录不允许通过单条或批量接口改写、删除；已有领料行的草稿须先清理行，才能改挂其他工单。执行前核对全部行与明细的归属、物料和数量，再按同一组已验证明细完成库存扣减与线边入库。

销售通知支持分批履约，同一通知行的实际已发数量与未过账占用合计不得超过计划数量；出库草稿也占用额度，取消或删除草稿后释放。通知仅在每行实际出库流水足额后完成，销售退货不冲回原通知的履约数量。保存、拣货和执行均重验客户、通知归属、指定批次及必检 OQC，过账与通知状态在同一事务中提交。历史完成状态与流水不符、已删除的发货证据或跨通知错链会显示待核查并阻止继续履约；升级保留原数量与流水，不自动修平历史差异。

跨工序报工须选择本次实际使用的相邻前序报工并分配数量；草稿可暂不完整，提交和审核时核对，审核与实际扣料在同一事务中冻结来源。待检报工也占用已消耗的来源份额。批次追溯根据冻结来源链连接各工序实际耗料与最终产出，支持分流和合流；同一库存批次可能汇总多次报工，不能据此声称单件精度。历史已扣料报工保留缺证标识，既有草稿须补齐来源后才能提交。

实际成本取自真实入库价格、FIFO 耗料及各工序实际工时/费用。缺失依据显示“待核定”，不会用标准价补齐。零费用须明确录入，误录工时可带原因撤销并保留审计记录；结算后禁止修改。历史库存没有价格依据时保留不完整成本。前序损耗结案后，需有成本结算权限的人员填写依据，明确核定“全部实际投入成本由合格产出吸收”，再另行结算；缺少成本证据、没有合格产出或存在末序不良时不能按此规则核定。末序不良的报废、返工和分摊仍需完整处置，不能将不良品计入合格品分母。销售退货目前缺少原出库行关联，退货成本同样保留待核定；单张出库毛利不等于含退货的财务净销售报表。客户门户仅展示参考售价，不暴露内部成本及毛利。

## 环境要求

当前启动脚本面向 Windows。以下工具需要安装并加入 `PATH`：

| 工具       | 版本要求                    |
| ---------- | --------------------------- |
| Git        | 可使用 `git` 命令           |
| JDK        | 17                          |
| Maven      | 3.9.x                       |
| Node.js    | ≥22.13.0，推荐 24 LTS       |
| pnpm       | 11.25.0，按下方命令安装     |
| Python     | 3.12+                       |
| PowerShell | 7.2+，使用 `pwsh` 命令      |
| MySQL      | 8.0，安装服务端和客户端程序 |

MySQL 程序需位于 `C:\Program Files\MySQL\MySQL Server 8.0\bin`，当前脚本按此位置查找程序。首次安装和启动需要访问 npm、Maven 仓库、PyPI 及 GitHub；脚本自动准备 Redis 和人脸模型运行时，并校验模型摘要。

Java 优先使用 `JAVA_HOME\bin\java.exe`，未设置 `JAVA_HOME` 时从 `PATH` 查找；Maven、Node.js 和 PowerShell 从 `PATH` 查找。`JAVA_HOME` 如已设置，必须指向有效的 JDK 17 安装目录。`deploy/machine-local.ps1` 也使用这些环境变量，不再依赖某位开发者的用户目录。

## 首次启动

在 PowerShell 7 中依次执行：

```powershell
git clone https://github.com/ColdneonG/FazeMES.git
cd FazeMES

npm install --global pnpm@11.25.0
python -m pip install -r deploy/requirements.txt
pnpm --dir frontend install --frozen-lockfile

mvn -B -ntp -f backend/pom.xml -pl yudao-server -am package -DskipTests
pwsh -NoProfile -File deploy/start-local.ps1
```

启动脚本会创建本地 MySQL 实例、导入初始化 SQL 和示例数据，并启动 Redis、本地人脸服务、后端及 Vite 前端。客户账号与产品目录需在“客户门户管理”中开通、发布；模型 API Key 在“AI助手与知识库”的模型配置中填写。外部模型调用还需管理员在“用量与预算”明确保存并启用调用配额；Jev及连接测试共用预算，改模型或密钥不会重置累计用量。

| 项目     | 默认值                             |
| -------- | ---------------------------------- |
| 前端     | <http://127.0.0.1:5173>            |
| 后端 API | <http://127.0.0.1:48080/admin-api> |
| 租户     | 示例企业                           |
| 管理员   | `admin` / `MesLocal@2026`          |

以上账号仅用于本机开发环境。服务监听回环地址；MySQL、Redis 分别使用 3308、6381 端口。

## 日常开发

完整功能演示的角色准备、Broky 教学主线、90 分钟流程和专项功能清单，见[演示手册](deploy/DEMO-GUIDE.md)。

以下命令均在仓库根目录执行：

- 启动：`pwsh -NoProfile -File deploy/start-local.ps1`
- 停止：`pwsh -NoProfile -File deploy/stop-local.ps1`
- 更新代码或后端修改后：运行 `pwsh -NoProfile -File deploy/start-local.ps1 -Build`。已有安装先校验工具与配置并备份旧 JAR，再停止受管理后端、执行待应用的数据库迁移、构建和启动新后端，避免旧代码在质量核查和结构升级期间继续写入，也避开 Windows 对运行中 JAR 的文件锁。
- 仅重建并重启后端（MySQL 和 Redis 已运行）：`pwsh -NoProfile -File deploy/restart-backend.ps1 -Build`。

前端使用 Vite 热更新。本地运行配置、随机密码、MySQL 数据、附件和日志保存在 `.runtime/`，该目录不提交 Git。

迁移或构建失败时后端保持停止，数据库及其他服务继续保留。修复后再次运行 `-Build`；仅在确认兼容已应用迁移时，才可恢复 `.runtime/backups/yudao-server.previous.jar`。备份仅在此前存在可运行 JAR 时生成。日常恢复启动也会先停止受管理后端，再执行迁移和重新启动。

更新前请使用 MySQL 备份工具备份 `yudao_mes`，并另存本地配置。已有安装的日常启动只复用原数据，并通过 `fazemes_schema_migration` 的文件名和 SHA-256 记录顺序执行待应用迁移，不再导入初始化 SQL 或示例数据。同日迁移按声明的先决依赖排序，例如 Broky 产品配置会等待成本和受控 SOP 表就绪。已执行迁移的内容如有变化会中止，请添加新迁移文件。`-InitializeDatabase` 只用于显式的首次初始化或配置修复，不是日常升级命令；已有数据但配置不完整时，默认启动会报错，不会自动重新导入数据。

## 目录结构

```text
backend/    Spring Boot 后端
frontend/   Vue 3 管理端
database/   初始化 SQL、示例数据与迁移脚本
deploy/     本地启动脚本及辅助工具
.runtime/   本地运行数据，启动后生成
```

## 当前限制

本项目处于本地开发与适配阶段。实际质检标准、设备采集、现场终端、打印及 ERP 接口仍需结合工厂需求适配。报表设计限于内置数据集；大屏按现有业务记录统计。库存出库禁止负数，线边库存和预占按工单隔离；Redis 使用无持久化的开发配置。

知识库当前使用 BM25 词法检索，生成回答需要配置模型服务和调用预算；仅检索文档、规则查询及人工业务流程不依赖模型预算。用量缺失时保留待核定占用，金额按管理员配置价格估算，计量启用前的历史用量未知。扫描 PDF 需要先做 OCR。人脸核验不含硬件活体检测，需要本人在页面授权摄像头并完成录入。
